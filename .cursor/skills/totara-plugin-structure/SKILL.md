# Totara Plugin Structure

## Core principles

- Plugins are **self-contained**: no direct core changes. Use hooks, events, or overrides to interact with core. If a hook is missing, request one from Totara Support.
- Each plugin has a **frankenstyle name**: `type_plugin_name` (e.g. `local_myplugin`, `mod_assign`, `auth_saml`). The `type` maps to a directory defined in `\core_component::fetch_subsystems()`.
- A plugin lives in **two separate directory roots** — one for server (GPL), one for client (proprietary):

| Root | Path |
|------|------|
| Server | `server/<type>/<plugin_name>/` |
| Client | `client/component/<frankenstyle>/` |

---

## Server root — quick reference

| Path | Purpose |
|------|---------|
| `version.php` | Plugin registration: version, required Totara version, frankenstyle component name |
| `index.php` | Default web entry point (also prevents directory listing on misconfigured servers) |
| `settings.php` | Site admin settings, added to the admin tree at install |
| `lib.php` | Legacy function library for Moodle subsystem integration (optional; prefer autoloaded classes) |
| `upgrade.txt` | Running log of breaking changes and dev notes across versions |
| `classes/` | All autoloadable PHP classes under the `\type_plugin_name` namespace |
| `db/` | System definitions: schema, capabilities, hooks, events, caches, services |
| `lang/` | Localisation strings used in front end and notifications |
| `webapi/` | GraphQL schema files (`.graphqls`) and persisted query definitions (`.graphql`) |
| `rb_sources/` | Report Builder source and embedded report definitions |
| `tests/` | Unit tests (`*_test.php`) and Behat acceptance tests (`tests/behat/*.feature`) |
| `pix/` | Plugin images, overridable by themes |
| `templates/` | Mustache templates, overridable by themes |
| `backup/` | Backup/restore code for course-context data |
| `amd/src/` | AMD JS modules — **legacy**, do not use for new code |
| `yui/` | YUI modules — **legacy**, do not use for new code |

---

## Client root — quick reference

| Path | Purpose |
|------|---------|
| `tui.json` | Registers the bundle with Tui; declares vendor, dependencies, optional entry point |
| `src/` | Vue and JS source (see v1/v2 detail in client reference) |
| `build/` | Compiled output generated by `tnpm run tui-build` — do not edit manually |
| `upgrade.txt` | Client-side breaking changes log |
